# Security Policy

## Safety Model

Ant Farm is designed as a **local-only, safety-first** multi-agent coding system. The following mechanisms are built into the tool to prevent accidental damage:

### 1. Isolated Patch Application

- Patches generated by worker ants are **never applied directly** to your main repository checkout.
- All patches are applied inside git worktrees created under `.antfarm/worktrees/`.
- You must explicitly choose the branch name when applying a patch, and you can inspect the diff with `antfarm task <id>` before committing to an application.

### 2. Worktree Directory Enforcement

- Ant Farm **refuses to run** from inside any `.antfarm/worktrees/` directory.
- Every CLI command resolves your current working directory and checks that it is not within a managed worktree. This prevents runaway agents from modifying their own operational data.

### 3. Patch Validation Before Application

- Every patch candidate is validated with `git apply --check` inside the target worktree before being applied.
- If the diff does not apply cleanly, the operation fails and the task is marked as failed — no partial or broken patches are stored.

### 4. Unified-Diff Normalization

- Patch diffs are normalized to a consistent unified-diff format before storage and application, preventing parsing errors that could lead to incorrect patch application.

### 5. File Glob Requirements

- Every mission `--files` glob must match at least one file in the repository. Blind wildcards (e.g., `**/*.py` when no Python files exist) are rejected with a clear error message.

### 6. Mission Abort on Invalid Patches

- If PatchAnt produces no validated diff for a task, the mission stops before attempting any worktree creation or patch application.

### 7. Verifier Timeouts

- All deterministic verifier commands run with configurable timeouts (default: 300 seconds). A hung or infinite verifier will not block the system indefinitely.

## Reported Vulnerabilities

If you discover a security vulnerability in Ant Farm, please report it responsibly:

1. **Do not open a public GitHub issue.**
2. Contact the maintainers directly with a detailed description of the vulnerability.
3. We will acknowledge your report within 48 hours and provide an expected timeline for a fix.

## Model Weight Disclaimer

- Ant Farm does not bundle or distribute model weights. You must source GGUF files from reputable providers.
- Verify the integrity (e.g., SHA-256 checksums) of any model file you download before using it with llama.cpp.
- The tool itself has no network access beyond connecting to `127.0.0.1` for local inference — it does not download or update models automatically.

## Known Security Considerations

- **Shell verifiers run on your machine** — verify commands (tests, linters) are executed via `subprocess.run(shell=True)` in the target directory. Only pass verified command strings to `--cmd`.
- **Network exposure** — llama.cpp servers bound to `127.0.0.1` are not exposed externally, but if you change the bind address, ensure appropriate firewall rules are in place.
